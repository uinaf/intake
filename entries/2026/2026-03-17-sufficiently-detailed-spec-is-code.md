Gabriella Gonzalez: a spec precise enough to generate working code is already pseudocode. You cannot escape the precision engineering requires.

## Key takeaways

- **Two misconceptions**: Specs are not simpler than code, and spec work is not inherently more thoughtful — speed-optimized specs become slop too.
- **Symphony evidence**: SPEC.md is prose dumps of schemas and algorithms — thinly veiled code, and it still failed to generate a working Haskell port.
- **YAML lesson**: An extremely detailed spec plus a conformance suite still does not produce conforming implementations.
- **Dijkstra**: Formal symbolism exists because natural-language precision does not scale.
- **Borges map**: Expanding the spec to fix flakiness approaches a map the size of the territory.
- **Delivery time**: Specifications were never time-saving devices; if optimizing for delivery, write the code.
