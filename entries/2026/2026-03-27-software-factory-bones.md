Blog post by David Crawshaw (exe.dev), shared on X with the take: "No-one has figured out how an eng team should work with agents yet. Be wary of anyone telling you they know how to do it. Keep exploring."

## Key Takeaways

- **Don't declare The Solution yet.** Dev Productivity engineering pushing a single workflows are being counterproductive. The moment calls for experimentation and giving people agency to iterate.
- **The compute primitive is key.** Plentiful, performant, trivial-to-provision VMs — accessible from anywhere, shareable, secure, trusted with your data. Given this, agents/automations/workflows naturally emerge.
- **Everyone's workflows is different.** 7 people at exe.dev → 9 different workflows. Multi-agent orchestrators, vanilla Claude Code, pi coding-agents agent, their own agent (Shelley), Slack newsletter bots, test-flake fighters, inbox views across VM agent states.
- **The common denominator: VMs for isolation.** Isolate, try, share, iterate, parallelize. The successful workflows evolve to become the "bones" of the software factory.
- **This is not a One Size Fits All moment.** It's an "Everyone's Workflow is Different" moment.

## Notable thread reply

@BoMiaoFinance: "We're trying to fit agents into human workflows shapes. PRs, sprints, code review — all designed around human throughput and error patterns. The right unit of work for an agent isn't a PR, it's a test-passing diff. Agents don't need code review — they need eval."
