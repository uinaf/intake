DHH explains why capable coding agents—not a philosophical conversion—moved him from typing every line to starting almost every task with an agent. The leverage expands ambition, but makes taste, review, and sustainable judgment more important.

## Key takeaways

- **Capability threshold**: Autocomplete disrupted DHH’s thinking and rarely met his standards; terminal agents became useful once they could inspect repositories, operate tools, revise work, and produce code worth reviewing.
- **Agent-first loop**: He now asks an agent for the first draft, reviews the diff, then commits, redirects, or edits it. Human-readable code and architectural fit remain requirements, not optional polish.
- **Cheaper exploration**: The bigger gain is not faster execution of a fixed backlog but making speculative ideas, neglected optimizations, and previously unaffordable reviews cheap enough to attempt.
- **Taste as bottleneck**: As implementation gets cheaper, value shifts toward choosing worthwhile problems, shaping coherent products, and recognizing whether generated work is correct, safe, and aesthetically consistent.
- **Uneven leverage**: Experienced engineers benefit first because they can supervise parallel work and catch subtle failures, while juniors risk losing the implementation tasks through which that judgment was traditionally developed.
- **Agent interfaces**: Command-line tools are the practical bridge for agents today because they expose composable, inspectable operations; browser-only autonomy is still too unreliable to replace explicit interfaces.
- **Sustainable pace**: Rapid shipping creates an addictive reward loop. DHH argues that AI is not a limited-time opportunity, so sacrificing sleep, health, or family for constant agent supervision is bad engineering and bad math.
