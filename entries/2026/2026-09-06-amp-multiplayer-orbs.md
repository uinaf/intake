Amp adds multiplayer to orbs, treating the running agent environment as a shared unit of work that includes the problem, code, and executable result rather than only a conversation transcript.

## Key takeaways

- **Explicit activation**: A user enables multiplayer for an orb through its thread menu on the web.
- **Workspace collaboration**: Once enabled, anyone in the workspace can join the thread and send messages to the agent.
- **Shared working surfaces**: Participants can access the orb's portal, file changes, and shared terminal alongside the conversation.
- **Time-bounded access**: The announced access lasts until multiplayer mode expires; the post does not specify the expiration duration or a detailed permission model.
- **Unit of work**: Amp argues that orbs increasingly combine task description, implementation, and running computation, making the environment itself the object teammates collaborate on.
