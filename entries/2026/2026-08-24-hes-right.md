Theo argues that agents have largely solved tactical code generation, but not software engineering. The bottleneck is now the verification loop: systems that let agents run, inspect, prove, and revise their work before users become the testers.

## Key takeaways

- **Coding versus engineering**: Turning a sufficiently clear request into functioning code is increasingly automated, while planning, architecture, validation, rollout, and long-term codebase health remain distinct engineering work.
- **Missing verification**: An agent-authored pull request does not imply that anyone ran or observed the changed behavior, so plausible code can ship obvious product bugs that static review will not reveal.
- **Executable evidence**: Agents need cheap, repeatable access to realistic environments plus screenshots, videos, traces, and other artifacts that prove the result rather than merely describe the implementation.
- **Reviewer role**: Code review still matters for architecture, scope, inappropriate dependencies, and missing tests, but behavioral defects increasingly require an independent reviewer or verifier that exercises the software.
- **Harness responsibility**: Repositories that are difficult for humans to start and test are even harder for agents; build, preview, fixture, rollback, and observation paths are therefore part of the agent harness.
- **Closed feedback loop**: Failed verification should route back to implementation or planning with concrete evidence, creating an autonomous generate-test-review-revise loop instead of treating the first pull request as completion.
- **Strategic judgment**: Agents can contribute analysis and experiments to strategic decisions, but humans still need to design the pipelines, quality bars, and escalation points that constrain autonomous execution.
